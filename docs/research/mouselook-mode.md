# 可切換滑鼠視角模式

## 目標

在不改變預設操作的前提下，替一般 3D 探索加入可選用的滑鼠視角操作。這仍是原引擎的格狀移動與事件系統，不改成連續物理移動；所有人物、門、容器、屍體與劇情物件仍走既有滑鼠左鍵互動派送。

## 測試版操作

- `F2`：切換滑鼠視角模式；每次啟動遊戲時預設關閉，本次遊戲期間保留狀態。開啟後 3D viewport 會擴張到完整 320×200 畫面。
- 滑鼠左右移動：水平旋轉視角；滑鼠向上抬頭、向下低頭，限制在基準視角上下各約 11.25°。
- `W`／`S`：前進／後退。
- `A`／`D`：向左／向右平移；方向鍵仍保留左轉／右轉。
- `Q`：保留向左平移；`E` 改為啟用準星指向的物件。
- 滑鼠左鍵：在捕捉狀態下同樣啟用準星指向的物件。
- 按住 `Ctrl`：暫停視角控制、隱藏準星，恢復經典 3D viewport、完整 UI 與原先游標位置；放開後重新進入全畫面並捕捉滑鼠。
- 按住 `Tab`：繼續顯示全部有效熱區；準星目前指向的物件以黃色框線標示。

準星使用當前 3D viewport 的中心；FPS 全畫面期間就是 `(160,100)`。無目標時是灰色，有目標時轉為黃色。模式切換會顯示兩秒中文提示。

## 實作原則

- `WCURSOR.C` 將原本的滑鼠互動拆成座標目標解析與互動執行。一般模式傳入實際游標位置；滑鼠視角模式傳入 viewport 中心，因此兩種操作共用完全相同的物件優先順序與事件函式。
- 中心感應只接受原本滑鼠即可互動的 `WorldHotspot` 類型；多個框重疊時沿用原本由後往前掃描的命中優先序。
- 視角捕捉只存在於 `world3d_main_loop()`。開啟施法、地圖、世界地圖、紮營、存檔選單、角色資訊、物品欄或物件互動前會先恢復游標，返回 3D 後再捕捉。對話會在 3D 主迴圈暫停期間執行，所以不能等待 Ctrl 輪詢；第十三輪改由 `dialog_show_by_key()` 與 `dialog_play_record()` 兩個共用入口主動釋放捕捉，開始顯示前立即恢復游標。第十四輪發現城鎮不一定經過對話入口，因此將共用函式泛化為 `worldloop_mouselook_release_for_modal()`，並在傳送場景、隊伍狀態事件、地面物品、熱區啟動、熱區後續事件及密技城鎮六個世界事件邊界統一呼叫；這些邊界涵蓋城鎮、商店、旅店、神殿、遭遇、戰鬥、區域切換與腳本畫面。離開各介面後均由 3D 下一幀自動重新捕捉。
- `A`／`D`／`E` 只在實際鍵盤鍵按下時重映射；用 `Ctrl` 恢復游標後點擊畫面上的原生方向按鈕，按鈕 action 不會被誤改。
- 原滑鼠互動會在按下與放開兩幀之間建立 `g_wMenuDragState == 1`，物件處理器用它區分左／右鍵語意。E 不能只直接呼叫派送，也不能把物件事件執行兩次；第六輪會複製目前準星命中的 hotspot、釋放捕捉，再暫時模擬一次完整左鍵狀態並只派送一次。
- `F2` 與 `E` 都有按鍵邊緣防重複，按住不會反覆切換模式或連續觸發互動。
- 滑鼠向右移沿用引擎右轉時「yaw 減少」的方向慣例。第六輪的 INT 33h function `0Bh` 在未捕捉的 DOSBox-X 整合模式下會依設計回傳零，當時因此撤除；第十一輪加入 `autolock=true` 與 `mouse_emulation=locked` 後，DOSBox-X 會在點入遊戲時啟用 SDL relative mouse mode，`0Bh` 才會提供不受游標位置與畫面邊界影響的真正相對 motion counter。第十二輪正式改回以 `0Bh` 為主要輸入，移除 3D viewport clip、邊界鎖與任何重置中心操作；未完成 host 捕捉前才暫用全畫面絕對座標差，而且絕不 recenter，因此最多在 host 畫面邊界暫停，不會製造持續單向旋轉。相對 counter 乘 4 換算為既有 quarter-pixel 尺度，使水平／垂直手感仍等同每 driver unit `0x02`／`0x01` binary-angle units，保持無 Dead Zone、無加速、無平滑。若仍需更低，須改用固定小數與餘數累積，才能低於整數倍率 `1` 而不吃掉微小移動。
- 成功的普通移動步伐也會呼叫 `hotspotevt_disp_pending_events()`，即使沒有任何 pending flag；因此不能在整個 dispatcher 外無條件釋放捕捉。第十五輪把釋放移進實際 pending event 的 switch，只在兩種城鎮、遭遇、怪物交談、陷阱／戰鬥與區域切換六類接管畫面的事件前執行；純移動、音效與機率事件不動捕捉，長按 W 時便能持續輪詢滑鼠視角。
- 第十六輪會在每次進入 `world3d_main_loop()` 時保存資料檔提供的經典 viewport `(13,11,294,101)`；FPS 捕捉時暫改為 `(0,0,320,200)`，並略過經典 menupage、狀態 caption 與羅盤。Ctrl、F2 關閉、modal／事件及主迴圈離開時均從保存值還原，而非寫死座標；恢復 UI 時完整重繪經典 frame。E 模擬左鍵只暫停捕捉、不還原 viewport，避免單純開門等互動閃出 UI。全畫面渲染後的雙 VGA page 同步範圍改為 0–199 行，經典模式仍保留原本的 11–138 行。第十七輪因實測發現既有水平 band filler 寫死 columns 13–306、普通戶外地面背景又只填 12 行，新增 clip-aware 全寬填色與延伸地面底色；沉浸模式也暫時把 zoom 降一級，避免近地面多邊形在加倍高度中被過度放大，恢復經典版面時會一併還原原 zoom。
- 第十八輪改為安全的 compositor 路徑：世界 renderer 維持原始 viewport，以較廣角的 zoom 繪製後只取中心 160×100，借用 VGA Page 1 保存來源，再逐 plane 精確 2× 放大至 Page 2 的 320×200。這會保留原生像素比例，不讓 renderer 看見舊 UI 下方原本刻意隱藏的近距離地形；準星／E 使用來源中心，Tab 與目標框則換算成全畫面座標。
- 第十九輪在第十八輪確認無貼圖錯誤、但解析度不足後，將來源提高到置中的 288×180、恢復經典 zoom 7，再做 10:9 等比例放大；垂直角度範圍仍小於上一個安全版本，但來源已涵蓋最終畫面的 81% pixels。上一版以 `backup/fps-fullscreen-safe-2x-20260905` 保留。
- R3D 的投影中心、clip rectangle、天空／地面與 hit-test 都由 `ViewContext.viewport` 推導，`ts_create_fullscreen_view()` 原始預設也正是 320×200，因此這個 POC 不改投影器或資料格式。代價是每幀填色面積從 `294×101 = 29,694` 增至 `320×200 = 64,000` pixels，約 2.16 倍；流暢度及原本看不到的上下視野是否出現場景缺口須靠實機驗證。
- 第三輪誤改了只供另一條 render path 使用的 `g_nWorldViewYawNormal`，但 FPS 熱區渲染實際由 `world_render_frame_with_hittest()` 直接讀取 `g_world_widget->camera`。第四輪已改為調整真正的 `g_world_camera->base.orientation.pitch`；世界移動與碰撞仍只使用 yaw。捕捉期間暫時套用受限 pitch offset，按 Ctrl、進入 modal、關閉 F2 或離開 3D 時恢復基準 pitch，重新捕捉後再套回偏移。

## 實機驗收清單

1. 冷啟動後仍是一般模式；`F2` 顯示「滑鼠視角模式：開」後，3D 應鋪滿整個 320×200 畫面且不留經典 UI；再次按下顯示「關」並完整恢復原版面。
2. 滑鼠左右移動方向正確、沒有自行漂移；移動速度不會過快或過慢。
3. `W/S/A/D` 分別前進、後退、左平移、右平移；方向鍵仍能前後移動及左右轉向；`Q` 仍可左移。
4. 分別對人物、門、寶箱／袋子、地上物品或屍體測試：準星進入熱區時變黃並框出單一目標；`E` 與左鍵各只觸發一次正確互動。
5. 準星對著物件時按住 `Tab`，應同時看見全部白色熱區框與目前的黃色目標框；放開後只留下目前目標。
6. 按住 `Ctrl` 後經典 3D 視窗、邊框、人物、按鈕與游標應完整恢復且可以點擊；放開後重新鋪滿全畫面、游標消失、準星恢復且視角不跳動。
7. 依序開啟並離開施法、近距離地圖、世界地圖、紮營、遊戲選單、角色資訊與物品欄，確認各畫面游標正常，返回探索後自動恢復滑鼠視角。
8. 走入劇情對話及用 E 觸發人物對話，確認對話開始時游標出現、不需按 Ctrl 即可翻頁或點選選項；對話結束回到探索後自動恢復滑鼠視角。
9. 進入城鎮並操作其中的商店、旅店或神殿；另測試地面物品、遭遇／戰鬥及區域切換，確認各畫面游標存在，返回探索後自動恢復滑鼠視角。
10. 關閉模式後，A/D 左右轉、Q/E 左右平移、滑鼠點物件與 Tab 全熱區框均維持原行為。
11. 順帶確認 F5／F9、C、M、F、T、O、B 與 1／2／3 等既有熱鍵沒有迴歸。
12. 比較全畫面前後的轉向及長按移動流暢度，並查看戶外天空／地面、森林／城牆、室內與地城上下緣是否有空白、殘影、破面或物件異常消失。

## 首輪實測結果（2026-09-05）

- A／D 平移方向正確。
- Ctrl 暫時恢復 UI 游標正常；進出地圖、物品欄、紮營與選單後也會正常恢復視角捕捉。
- F2 關閉後的舊操作維持不變。
- 第一版滑鼠轉向過快，第二版減半後仍不跟手；第五版又確認反向時會先轉完舊方向，且 E 無作用。第六版補齊 E 的左鍵狀態，但相對 motion counter 在目前環境無輸入；第七版改成相容的逐幀座標差與低頻邊界重置後，使用者確認視角改善很多且 E 已正常。第八版再降靈敏度，第九版改為 X／Y `0x02`／`0x01`；第十二版搭配 DOSBox-X 捕捉改用真正相對輸入後，使用者確認手感大幅改善。第十三版的對話游標釋放與返回探索恢復、第十四版的城鎮游標均已通過實機驗收；第十五版後使用者回報整體感覺已接近定案。第十六版實測確認移動與視角正常，但直接擴 viewport 會暴露硬編碼背景填色限制而破圖；第十七版消除殘框與未填背景後，仍證實下半部是原生近地面低多邊形。第十八版 2× 合成已確認無貼圖錯誤，但解析度不足；第十九版 288×180 高解析合成待實測。
